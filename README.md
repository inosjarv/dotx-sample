# doc-dotm-service

Generate Word documents (`.docx`) that use the styles of a Word template (`.dotm`) — with Java 25 and docx4j 17.

```java
var template = DotmTemplate.loadResource("templates/sample-template.dotm");
template.newDocument()
        .fill("customerName", "Acme Ltd")                 // content control, by tag
        .paragraph("Title", "Quarterly Report")           // paragraph style, by style ID
        .paragraph("Normal", p -> p.text("Revenue grew ").run("Strong", "12%"))
        .table("TableGrid", List.of(List.of("Region", "Q3"), List.of("EU", "1.4M")))
        .save(Path.of("target/report.docx"));
```

The output carries the template's styles, theme, numbering, headers/footers and page setup, and is saved as a plain macro-free `.docx`.

## Setup

Requires JDK 25+ (the build enforces it). If `mvn -v` shows another JDK:

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 25)   # macOS
mvn verify
```

## Try it

```sh
# Generate report.docx from the bundled sample template
mvn -q compile exec:java
open target/report.docx

# Generate report-dotx.docx from the hand-written .dotx (shading, spacing, table borders, links)
mvn -q compile exec:java -Dexec.mainClass=dev.docdotm.DotxDemo
open target/report-dotx.docx

# List the style IDs in any template
mvn -q exec:java -Dexec.mainClass=dev.docdotm.StyleInspector -Dexec.args=src/main/resources/templates/sample-template.dotm

# Regenerate the sample template
mvn -q exec:java -Dexec.mainClass=dev.docdotm.SampleTemplateGenerator
```

## Style IDs vs. display names

Every style in `word/styles.xml` has two identifiers:

| Style ID (in the XML, used by code) | Display name (shown in Word) |
|---|---|
| `Heading1` | heading 1 |
| `TableGrid` | Table Grid |
| `CalloutNote` | Callout Note |

Paragraphs reference the **ID** (`<w:pStyle w:val="Heading1"/>`). If the ID doesn't exist, Word silently renders `Normal` — so this project checks every ID against the template when you add content:

```
UnknownStyleException: Style ID 'Headng1' is not defined in the template; did you mean 'Heading1'?
UnknownStyleException: 'heading 1' is a display name, not a style ID; the style ID is 'Heading1'
StyleTypeMismatchException: Style 'Emphasis' is a character style, not a paragraph style
```

`template.styles().idForName("Heading 1")` resolves a display name to its ID.

## Using your own .dotm

1. **Inspect** it to see its style IDs:
   ```sh
   mvn -q exec:java -Dexec.mainClass=dev.docdotm.StyleInspector -Dexec.args=/path/to/house-style.dotm
   ```
   ```
   STYLE ID     TYPE       DISPLAY NAME
   CalloutNote  paragraph  Callout Note  [custom]
   Heading1     paragraph  heading 1
   ...
   ```
2. **Copy** the IDs you need into a constants class, like [`SampleStyles`](src/main/java/dev/docdotm/SampleStyles.java).
3. **Verify** them in a unit test, so a template edit that drops or renames a style breaks the build:
   ```java
   MyStyles.verify(DotmTemplate.load(Path.of("house-style.dotm")).styles());
   ```
4. **Generate**: `DotmTemplate.load(path).newDocument()...save(out)`. Load the template once and reuse it; each `newDocument()` starts from a fresh copy.

Notes:
- Only styles actually defined in the template's `styles.xml` are usable. A Word built-in that has never been used in the template (e.g. `Heading5`) is not defined yet — apply it once in Word and save the template.
- Content controls (Developer → Plain Text Content Control, with a **Tag** set in Properties) are placeholders you fill with `fill(tag, value)`, in the body, headers or footers. Body controls are kept where the template puts them and new content is appended after them; use `newDocument(ContentControls.DROP)` for an empty body.
- Macros (`vbaProject.bin`) and the template link are removed from the output.
- Tables span the text width between the template's left and right page margins, with equal columns. The first row is the header row: table-style header formatting applies to it, and it repeats at the top of each page.
- Links: `p.link("our website", "https://example.com")` shows the text, stores the URL as the link target, and uses the template's `Hyperlink` style. Only absolute `http`, `https` and `mailto` URLs are accepted.
- Anything the builder does not cover: `builder.unwrap()` gives the docx4j `WordprocessingMLPackage`.

## The sample template

`src/main/resources/templates/sample-template.dotm` is generated by [`SampleTemplateGenerator`](src/main/java/dev/docdotm/SampleTemplateGenerator.java) from docx4j's own styles:

- docx4j's default styles (`Normal`, `Title`, `Subtitle`, `Heading1`–`3`, `Header`, `Caption`, `Emphasis`, `TableGrid`, …),
- Word built-ins activated from docx4j's known-styles catalog (`Quote`, `IntenseQuote`, `ListBullet`, `Footer`, `Strong`),
- a house-style override (Georgia, dark teal) on `Title` and `Heading1`, so it is visible that output uses the template and not docx4j's defaults,
- one custom style, `CalloutNote`,
- content controls `customerName` (body) and `documentDate` (header), and a footer.

It has no VBA code; the macro-removal path is covered by a test fixture.

## The sample .dotx (hand-written XML)

`sample-template.dotx` is not committed as a binary. Its parts are plain XML under
[`src/main/template/sample-dotx/`](src/main/template/sample-dotx), mainly `word/styles.xml` and `word/document.xml`.
The build zips them (`maven-antrun-plugin`, `generate-resources` phase) to
`target/classes/templates/sample-template.dotx`, which is on the classpath and is the file to open in Word.
Edit the XML, run any Maven build, and the change is in.

```java
var template = DotmTemplate.loadResource("templates/sample-template.dotx");
template.newDocument()
        .paragraph(DotxStyles.BODY_TEXT, p -> p
                .text("Revenue grew, with ").run(DotxStyles.SHADED_TEXT, "Europe up 17%")
                .text(". See ").link("our website", "https://example.com").text("."))
        .paragraph(DotxStyles.SHADED_PANEL, "Figures are unaudited.")
        .table(DotxStyles.TABLE_HEADER_RULE, List.of(List.of("Region", "Q3"), List.of("EU", "1.4M")))
        .save(Path.of("target/report.docx"));
```

What it defines:

| Feature | Where | Values |
|---|---|---|
| Page | final `sectPr` | A4; margins top 2.5 cm, bottom 2 cm, **left 4 cm**, right 2 cm (text width 8504 twips) |
| Spacing (before / after / line) | document defaults (= `Normal`), `BodyText`, `Heading1`, `Heading2` | 0 / 8 pt / 1.15; 6 / 12 pt / 1.5; 24 / 12 pt; 18 / 6 pt |
| Shading | `ShadedPanel` (paragraph), `ShadedText` (character) | fill `DEEAF6`, `FFF2CC` |
| Border colours | `TableBlue`, `TableRed`, `TableTwoTone` | `2E75B6`; `C00000`; outer `1F3864` / inner `BFBFBF` |
| Header rule | `TableHeaderRule` | no borders except a `1F3864` line under the bold header row |
| Links | `Hyperlink`, `FollowedHyperlink` | `0563C1` / `954F72`, underlined |

Notes:
- `Normal`'s spacing is in the document defaults, not on `Normal` itself. A paragraph style's own spacing overrides a table style's, so this lets the table styles keep cell text compact.
- Table cells are padded with table cell margins, not paragraph spacing, so rows lay out the same after a page break.
- IDEs (Eclipse/VS Code) don't run the antrun zip step. Run `mvn process-resources` once, or any Maven build, before running from the IDE, otherwise `loadResource` reports the template as not found.

## Layout

| Class | Purpose |
|---|---|
| `DotmTemplate` | Loads a template (file or classpath), exposes its `StyleCatalog`, creates documents |
| `DocumentBuilder` | Adds paragraphs/runs/tables with validated style IDs, fills content controls, saves `.docx` |
| `StyleCatalog` | Style ID ↔ display name ↔ type; `require()` validation with suggestions |
| `SampleStyles` | Style ID constants for the sample template + `verify()` |
| `DotxStyles` | Style ID constants for the sample `.dotx` + `verify()` |
| `StyleInspector` | CLI: list a template's styles |
| `SampleTemplateGenerator` | CLI: build the sample `.dotm` |
| `Demo` | CLI: build `target/report.docx` |
| `DotxDemo` | CLI: build `target/report-dotx.docx` from the `.dotx` |
